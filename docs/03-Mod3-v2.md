## Introducing the Normal Model

Many real quantitative variables are approximately bell-shaped (for example, heights, weights, and measurement errors). For these variables, we consider a theoretical or ideal **Normal model**.

**What is a model?**

A model is a theoretical or ideal concept, not the exact truth. Think of a plastic skeleton in a doctor's office: it isn't really a skeleton, and none of us have a skeleton exactly like it, but it still gives a great approximation to reality and is genuinely useful. The Normal model works the same way. No real variable probably has *exactly* a Normal distribution, but the model is still a useful approximation.

**Key features of the Normal model**

- In symbols, a Normal model is written $N(\mu, \sigma)$
- It is **perfectly symmetric**
- 50% of observations occur on one side of the mean and 50% on the other
- Normal curves are drawn to contain 100% of the observations, so **areas under the curve represent theoretical percentages** (or probabilities)

::: {.tipBox}
**Notation**

- The mean of a theoretical Normal model is $\mu$ ("mu")
- The standard deviation of a theoretical Normal model is $\sigma$ ("sigma")
- Recall: $\bar{y}$ is the mean of **actual (sample)** data, and $s$ is the standard deviation of actual (sample) data. $\mu$ and $\sigma$ describe the theoretical model; $\bar{y}$ and $s$ describe the data we actually collected.
:::

**Standard deviation as a ruler**

Areas under Normal curves depend only on how many standard deviations an observation is away from the mean. The number of standard deviations away from the mean is called $z$.

### The 68-95-99.7 Rule

For **any** Normal model:

- **68%** of observations are within 1 standard deviation of the mean
- **95%** of observations are within 2 standard deviations of the mean
- **99.7%** of observations are within 3 standard deviations of the mean

## Normal Distribution: Standardising

Normal distributions do not necessarily have the same means and standard deviations. Areas under a Normal curve depend only on how many standard deviations ($\sigma$) the observation ($y$) is from the mean ($\mu$). The number of standard deviations from the mean is called a **z-score**. Converting a score to a z-score is called **standardising**.

::: {.tipBox}
**The standardising formula**

$$z = \frac{y - \mu}{\sigma}$$

- $z$-scores are negative for observations below the mean, and positive for observations above the mean
- $z$-scores are numbers without units ("dimensionless")
- Always round $z$-scores to **2 decimal places**
:::

**Why standardise?** The z-score is useful because it:

- allows the probability of a score occurring within a Normal distribution to be calculated
- allows the comparison of two scores from **different** Normal distributions (even distributions with different units — we can compare apples and oranges!)

**The Standard Normal Model** has a Normal model shape, a mean of 0, and a standard deviation of 1. Any Normal model can be converted to a Standard Normal model, which means we can use the Standard Normal Table to work out probabilities.

**Comparing apples and oranges.** Suppose apple weights are approximately Normal with mean 136g and SD 25g, and orange circumferences are approximately Normal with mean 26cm and SD 4cm. Which is more unusual: an apple weighing 185g, or an orange with a 35cm circumference? We cannot compare grams to centimetres directly, but we can compare z-scores:

$$z_{\text{apple}} = \frac{185-136}{25} = 1.96 \qquad z_{\text{orange}} = \frac{35-26}{4} = 2.25$$

The orange has the higher z-score, so it is the more unusual of the two, even though we started with two completely different units of measurement.

::: {.tipBox}
**Steps to standardise and find a proportion**

1. Draw a diagram!
2. Compute the z-score using the standardising formula
3. Use the Standard Normal Table to find the proportion (or %)
4. Work out the answer
:::

The Standard Normal Table gives the area under a Normal curve **to the left** of the z-score you look up. If you need the area to the right, or between two z-scores, you will need to subtract from 1 or subtract one table value from another, exactly as in the worked examples in the tutorial.

## Normal Distribution: Unstandardising

Sometimes a problem works the opposite way around: instead of knowing an observation and needing to find a proportion, you know a proportion (or percentage) and need to find the corresponding observation. This is sometimes called an "unstandardising" or "backwards" problem.

We can use the Standard Normal Table "backwards": if we know an area or proportion, we can look up the corresponding z-score, and then use the **unstandardising formula** to convert that z-score back into an actual observation.

::: {.tipBox}
**The unstandardising formula**

$$y = z\sigma + \mu$$

Use a diagram whenever problem-solving with a Normal model!
:::

**Recognising an unstandardising context.** Before, we knew the observation ($y$) and sought a percentage. Now, we know the percentage, and seek an observation ($y$). This is the tell-tale sign of a "backwards" problem.

::: {.tipBox}
**Steps to unstandardise and find a value**

1. Draw a diagram!
2. Use the Standard Normal Table to find the z-score (read the table in reverse: find the area closest to the one you want, then read off the row and column to get z)
3. Use this z-score in the unstandardising formula, $y = z\sigma + \mu$
4. Work out the answer
:::

**Worked example.** The length of human pregnancies is approximately Normal with mean 266 days and standard deviation 16 days. What is the duration of the shortest 10% of pregnancies?

From Table Z, the area closest to 0.10 corresponds to $z = -1.28$. Using the unstandardising formula:

$$y = z\sigma + \mu = (-1.28 \times 16) + 266 = 245.52$$

So 10% of pregnancies are about 246 days or shorter.

(function(){
  const ROOT = document.getElementById("m3-checklist");
  const KEY  = "m3-checklist-v1";

  const boxes = Array.from(ROOT.querySelectorAll("input[type=checkbox][data-id]"));
  const bar   = ROOT.querySelector(".cl-bar");
  const stats = ROOT.querySelector(".cl-stats");
  const btnAll   = ROOT.querySelector('[data-action="all"]');
  const btnClear = ROOT.querySelector('[data-action="clear"]');

  function update(){
    const total = boxes.length;
    const done  = boxes.filter(b => b.checked).length;
    const pct   = total ? Math.round(100 * done / total) : 0;
    bar.style.width = pct + "%";
    stats.textContent = done + " of " + total + " completed (" + pct + "%)";
  }

  function save(){
    const state = {};
    boxes.forEach(b => state[b.dataset.id] = b.checked);
    localStorage.setItem(KEY, JSON.stringify(state));
    update();
  }

  function load(){
    const saved = JSON.parse(localStorage.getItem(KEY) || "{}");
    boxes.forEach(b => b.checked = !!saved[b.dataset.id]);
    update();
  }

  boxes.forEach(b => b.addEventListener("change", save));

  btnAll.addEventListener("click", () => { boxes.forEach(b => b.checked = true); save(); });
  btnClear.addEventListener("click", () => {
    if (!confirm("Clear all ticks for this checklist on this device?")) return;
    localStorage.removeItem(KEY);
    boxes.forEach(b => b.checked = false);
    update();
  });

  load();
})();
</script>
